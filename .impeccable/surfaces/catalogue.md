# Catalogue extension

Mode: Operate. Extend Menu & recipes and the existing POS; inherit DigitalBurj's confirmed visual system. Managers configure fixed bundles and independent variant SKUs; cashiers select the actual item, confirm ingredients and route one order. Guest ordering uses the same availability and component snapshots. Configuration errors, stock shortages and offline conflicts must be explicit.

## Direction contract

THESIS: Make a menu family's choices and a bundle's actual contents visible before acceptance.

OWN-WORLD: Existing fig actions, porcelain background, warm ruled rows, Manrope UI, Fraunces drawer titles. Shared fields, panels and drawers; no new visual identity.

STORY: Create recipe-bearing items, attach clearly labelled variants, or create a fixed-price combo with validated component options. Select the real variant or inspect fixed components; acceptance reserves their recipes and routes their stations.

FIRST VIEWPORT: Preserve the outlet menu table and heading actions. Add a secondary combo action. Item drawers contain variant controls after recipe evidence; combo drawers expose component rows, quantity, modifier choices and fixed price. POS family selection uses the existing drawer and price-bearing choice rows.

FORM: Narrow extension of the established surface; no concept seed applies. Signature interaction: choosing a variant carries its own price and modifiers into the order. Use inherited drawer entrance and reduced motion.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
